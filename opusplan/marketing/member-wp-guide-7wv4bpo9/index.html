1

このガイドについて

会社概要ページに「メンバー紹介」を新設します。そのために必要な準備と、公開後に毎回やることをまとめました。

完成イメージは、実際の会社概要ページに新しいパーツを差し込んだ形で確認できます（名前・数字はダミーです）。

完成イメージhttps://kanpai-web.github.io/share/opusplan/marketing/member-sallgebk/
記入シート（共有）タスク管理 ＞ メンバー紹介新設タブ

本番サイトを調べて分かったこと

調べたこと分かったこと
コラム・実績の「投稿者」どちらも投稿者を持たない作りになっています（REST API の応答に author がありません）。「この人が書いたコラム」を自動で出すには、投稿者欄を有効にする必要があります（STEP 2）
実績の「担当者」担当を表す項目はありません。「担当メンバー」の分類を新しく作ります（STEP 2）
WordPressのユーザー現在2アカウント（opusplan／渡邉さん）。メンバーの数だけアカウントを追加します（STEP 1）
ユーザー一覧の公開状態/wp-json/wp/v2/users で、ログインに使う名前が外部から見える状態です。アカウントを増やす前に、表示しないよう設定するのがおすすめです（STEP 2）

先に結論

見た目のパーツ（CSS・マークアップ）は用意済みです。決める必要があるのは「メンバーの情報をどこで管理するか」の1点で、ここで作業量と今後の運用が変わります（次の章）。

どの方法でも、公開後の運用は「コラムの投稿者を本人にする」「実績に担当メンバーのチェックを入れる」の2つだけで、プロフィールの「担当した実績」「書いたコラム」が自動で更新されます。

2

メンバー情報の管理方法（打合せで決めること）

3つの方法があります。人数と、今後どれくらい入れ替わるかで選んでください。

方法向いているケース気をつけること
案A会社概要のテンプレートに直接書く4名程度で、入れ替えや修正がほとんど無い場合。最初の作業がいちばん少なく済みますプロフィールを直すたびにコーダーさんへの依頼が発生します。いまの人数なら回りますが、人が増える・こまめに直したい場合には向きません
案BWordPressのユーザーのプロフィール欄に持たせる載せる全員がコラムを書く場合。コラム末の「執筆者情報」と同じデータを使い回せます記事を書かない人（営業の方など）にもアカウントが必要になります
案Cカスタム投稿「メンバー」を作る人数が増えることを見込む場合はこちらを提案します。記事一覧と同じ感覚でメンバーを追加・修正・並べ替えでき、アカウントを持たない人も載せられます最初の実装が3案の中でいちばん多くなります。執筆者とのひも付けは「WordPressユーザー」を選ぶ欄で行います

打合せで確認すること

  • 掲載する人数（いまの4名で固定か、今後増える見込みがあるか）→ 管理方法（案A／B／C）を決める
  • 記事を書く人と書かない人の内訳（案Bにするかどうかに関わる）
  • 顔写真の撮影可否と、撮影のタイミング
  • WordPressのアカウント作成をだれが行うか（管理者権限を持っている方）
  • ACF などのカスタムフィールド用プラグインが入っているか（コーダーさんに確認）

※ 以降の手順は案B・案Cを前提に書いています。案Aの場合は STEP 2 の入力欄づくりが不要になり、STEP 4 でテンプレートに直接書いてもらう形になります（「担当メンバー」の分類と投稿者欄は、どの案でも必要です）。

STEP 1　アカウントを作る

管理画面の「ユーザー ＞ 新規追加」から、メンバーごとに1つ作ります。

項目入れるもの理由
ユーザー名ローマ字の名字（例 yamada）あとから変更できません。「担当メンバー」の分類と同じ綴りにそろえます
メールアドレス本人の業務用アドレスパスワード再設定に使います
名・姓漢字で
ブログ上の表示名「山田 太郎」（漢字フルネーム）コラムの執筆者として表に出る名前です
権限グループ記事を書く人：投稿者
書かない人：購読者（案Bのみ）		必要以上の権限を渡さないため。高寺・渡邉さんは現状どおり

案Cの場合

アカウントが必要なのはコラムを書く人だけです。営業の方などはアカウントを作らず、カスタム投稿「メンバー」に1件追加するだけで載せられます。

退職・異動のとき

アカウントは削除しないでください。削除すると、その人が書いたコラムの投稿者を別の人に付け替えるよう求められ、執筆者の情報が失われます。プロフィールの「掲載する」をオフにして、権限を「購読者」に下げる運用にします。

6

STEP 2　入力欄と分類を用意する（コーダーさん）

4つあります。①〜③はどの案でも必要、④は案B・案Cのときだけです。

① コラムと実績に「投稿者」欄を追加

いまはどちらの編集画面にも投稿者欄がありません。コラムは、これで「書いた人」から自動でプロフィールに並べられるようになります。

functions.php（投稿者欄の追加）
// functions.php
// コラム（blog）と実績（works）に「投稿者」欄を追加する
add_action( 'init', function () {
    add_post_type_support( 'blog', 'author' );
    add_post_type_support( 'works', 'author' );   // 実績は記録用（表示には担当メンバーを使う）
}, 20 );

// 投稿者アーカイブ（/author/ユーザー名/）にコラムを含める
add_action( 'pre_get_posts', function ( $q ) {
    if ( ! is_admin() && $q->is_main_query() && $q->is_author() ) {
        $q->set( 'post_type', array( 'blog' ) );
    }
} );

② 実績に「担当メンバー」の分類を追加

実績は複数人で担当することがあるため、投稿者ではなくチェックで複数選べる分類にします。ターム（選択肢）のスラッグは、STEP 1 のユーザー名と同じ綴りにしてください。

functions.php（担当メンバー）
// functions.php
// 実績の「担当メンバー」（チェックで複数選択）
add_action( 'init', function () {
    register_taxonomy( 'work_member', 'works', array(
        'label'        => '担当メンバー',
        'hierarchical' => true,          // チェックボックスで選ばせる
        'public'       => true,
        'rewrite'      => array( 'slug' => 'works/member' ),   // /works/member/yamada/ が担当実績の一覧になる
        'show_in_rest' => true,
    ) );
} );

※ 業種・成果の分類追加（実績ガイドの STEP 2）と同じ場所に書いていただくと管理しやすいです。

③ ユーザー一覧を外部から見えないようにする

アカウントを増やす前に入れておくのがおすすめです。セキュリティ系のプラグインで同じ設定ができる場合は、そちらでも構いません。

functions.php（ユーザー一覧の非公開）
// functions.php
// ユーザー一覧を外部から見えないようにする（ログインしていない場合）
add_filter( 'rest_endpoints', function ( $endpoints ) {
    if ( ! is_user_logged_in() ) {
        unset( $endpoints['/wp/v2/users'], $endpoints['/wp/v2/users/(?P<id>[\d]+)'] );
    }
    return $endpoints;
} );

④ プロフィールの入力欄（案B：ユーザー編集画面／案C：カスタム投稿「メンバー」）

記入シートの項目と1対1で対応させています。ACF が入っていればそれで、無ければやりやすい方法をご提案ください。

キー（案）ラベル形式・例
member_show掲載するオン／オフ
member_order表示順数字（1から）
member_photo顔写真画像（4:5の縦長・800×1000px目安）
member_romanローマ字表記Taro Yamada
member_role役職・肩書代表取締役／Webコンサルタント
member_areas担当領域3つまで（1行に1つ）。カードに #タグ で出ます
member_catchキャッチコピー30字前後
member_stat1_label / _value / _unit数字①Web集客の経験／15／年
member_stat2_label / _value / _unit数字②支援してきた企業／200／社以上
member_hobby休日のひとこと15字前後。写真の下に手書き風の文字で出ます
member_career経歴2〜4行（1行に1つ）
member_industries得意な業種士業／医療・クリニック
member_skills得意な施策1〜2行
member_certs資格・認定空欄可（空なら行ごと出ません）
member_consultsよく受けるご相談3つまで（1行に1つ）
member_value仕事で大事にしていること1〜2文
member_messageひとことメッセージ1〜2文。吹き出しで出ます
member_userWordPressユーザー（案Cのみ）ユーザー選択。書いたコラムを引くために使います
member_term担当メンバーのターム（案Cのみ）②の分類のターム選択。担当した実績を引くために使います

案Bでのひも付け

案Bでは、ユーザー名と「担当メンバー」のタームのスラッグをそろえることでひも付けます（例：ユーザー名 yamada ＝ ターム yamada）。案Cでは上の2つの選択欄で明示的にひも付けます。

7

STEP 3　データを入れる（高寺）

記入シートがそろったら、管理画面に転記します。既存の記事・実績のひも付けもここで一度だけ行います。

  1. プロフィール欄に、記入シートの内容を1人ずつ転記する（顔写真も設定）
  2. 「担当メンバー」の分類に、メンバーぶんのタームを作る（スラッグはユーザー名と同じ）
  3. 既存のコラム：書いた人が分かる記事は、投稿者をその人に変更する。分からない記事は opusplan のままで構いません
  4. 既存の実績：担当した人にチェックを入れる（記入シートの「担当した実績」欄を参照）

既存記事の投稿者を一括で変えるとき

コラムの一覧画面で記事にチェックを入れ、「一括操作 ＞ 編集」から投稿者をまとめて変更できます（①の投稿者欄が追加されたあとに使えます）。

STEP 4　会社概要にメンバー紹介を表示する（コーダーさん）

見た目は完成イメージのとおりです。マークアップとCSSはそのまま使えるようにしてあります。

渡すもの

ファイル中身
opus-member.cssメンバー紹介の追加スタイル（クラス名はすべて om- 始まり。既存テーマと衝突しません）
メンバー紹介_マークアップ.htmlセクション全体（カード4枚＋プロフィールの小窓）＋開閉・タブ切り替えのスクリプト

入れる場所

会社概要ページの「オーパスプランを知る」ボタンの後、<div class="l-access"> の直前です。

手書き風の文字（フォントの追加）

写真の下のひとことと吹き出しに、Google Fonts の Klee One を使っています。会社概要ページの <head> で読み込んでください。

head に追加
<link rel="stylesheet" href="https://fonts.googleapis.com/css2?family=Klee+One:wght@600&display=swap">

メンバーの並び

「掲載する」がオンの人だけを、「表示順」の小さい順に出してください。

「担当した実績」「書いたコラム」の自動表示

プロフィールの小窓の下部に、タブで切り替えて最新3件だけを小さなカードで出します。4件目以降は一覧ページへのリンクにします。

参考実装（最新3件と件数）
// 会社概要テンプレート：メンバー1人ぶんの「担当した実績」「書いたコラム」
// $user_id … メンバーのWordPressユーザーID／$slug … 担当メンバーのタームのスラッグ

$works = new WP_Query( array(
    'post_type'      => 'works',
    'posts_per_page' => 3,                      // 最新3件だけ見せる
    'tax_query'      => array( array(
        'taxonomy' => 'work_member',
        'field'    => 'slug',
        'terms'    => $slug,
    ) ),
) );
$works_total = $works->found_posts;             // タブの件数・「すべて見る（◯件）」に使う
$works_all   = get_term_link( $slug, 'work_member' );

$columns = new WP_Query( array(
    'post_type'      => 'blog',
    'posts_per_page' => 3,
    'author'         => $user_id,
) );
$columns_total = $columns->found_posts;
$columns_all   = get_author_posts_url( $user_id );

// どちらも0件なら、プロフィール内のこの欄自体を出さない
// 4件以上あるときだけ「すべて見る（◯件）→」を出す
表示する要素出どころ
カードの画像アイキャッチ（コラム・実績とも）
カードのタイトル実績：カード見出し（work_card_title、空なら投稿タイトル）／コラム：投稿タイトル
タブの件数found_posts
すべて見る のリンク先実績：/works/member/ユーザー名/／コラム：/author/ユーザー名/

相談ボタンについて

プロフィール最下部のボタンは「まずは気軽に相談する」で、お問い合わせページへの通常のリンクです。指名制ではないことが伝わるよう、上に「ご相談はチームでお受けしています」の一文を添えています。

STEP 5　日々の運用（高寺）

公開後は、記事や実績を出すときに1か所選ぶだけです。ここを忘れるとプロフィールに出ません。

タイミングやること結果
コラムを公開するとき編集画面の「投稿者」を書いた本人にするその人のプロフィールの「書いたコラム」に自動で出る
実績を公開するとき「担当メンバー」で担当した人全員にチェックその人のプロフィールの「担当した実績」に自動で出る
メンバーが増えたときSTEP 1（アカウント）→ プロフィール入力 → 担当メンバーのターム追加案A以外はコーダーさんへの依頼は不要
プロフィールを直すとき案B・C：管理画面で直すだけ／案A：コーダーさんに依頼
退職・異動のとき「掲載する」をオフ、権限を購読者に（アカウントは削除しない）メンバー紹介から外れ、書いたコラムの執筆者情報は残る

この2点は、コラムの入稿ガイド（STEP 4・5）と実績ガイド（STEP 3・公開前チェック）にも追記しています。

10

公開前のチェック

完成イメージと見比べながら確認してください。

  • 会社概要の会社情報の下・アクセスの上に「MEMBER／メンバー紹介」が出ている
  • 「掲載する」がオンの人だけが、表示順どおりに並んでいる
  • 写真の下に手書き風の文字でひとことが出ている（Klee One が読み込まれている）
  • カードを押すとプロフィールの小窓が開き、×・背景のクリック・Escキーで閉じる
  • 小窓を開いているあいだ、後ろのページがスクロールしない
  • 「担当した実績」「書いたコラム」のタブが切り替わり、件数が実際の数と合っている
  • 4件以上ある人だけ「すべて見る（◯件）」が出て、一覧ページに遷移する
  • 実績もコラムも0件の人は、その欄自体が出ていない
  • 資格など空欄の項目は、行ごと出ていない
  • SP幅で、メンバーが1人ずつ1列に並び、区切り線が入っている
  • SP幅で、小窓が全画面になり、写真が中央に出る
  • 外部から /wp-json/wp/v2/users を開いてもユーザー一覧が出ない
